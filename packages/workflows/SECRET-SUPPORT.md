# Secret storage and named-account support

Release checkpoint: `sanoma`, `@sanoma-ai/workflows` and `@sanoma-ai/app` **0.10.1**, `@sanoma-ai/connector-supabase` **0.4.9**, `@sanoma-ai/bridge` **0.5** with its matching platform packages, and `@sanoma-ai/connector-neon` **0.2**. Publication and consumer verification remain pending in [#471](https://github.com/Sanoma-AI/sanoma/issues/471); check installed versions before relying on these capabilities. The client pins [provider-bridge v0.2.0](https://github.com/Sanoma-AI/provider-bridge/releases/tag/v0.2.0); the Go binary release alone does not update installed npm packages. GCP provisioning and D1 runtime identity are separate work, outside this 0.10.1 checkpoint.

## Connector coverage

**Neon was the only connector in the 0.10.1 checkpoint declaring a named authentication method.** GCP's provisioning connection followed, with a stored bearer ([deployment identity](../../connectors/gcp/README.md#deployment-identity)). Its [authentication documentation](../../connectors/neon/README.md#authentication) describes the supported bundle and provider verification.

Supabase declares named methods too: `oauth`, by consent with the company's own OAuth application, and `accessToken`, a pasted token ([its accounts](../../connectors/supabase/README.md#accounts)). GitHub, Stripe and Docker resource drivers use the session-capable bridge, but do not yet opt into named authentication. Supabase Vault is a storage adapter, separate from the Supabase connector's accounts. Other connectors retain their existing authentication paths. Login, model and remote halves are also distinct from named operation accounts. This release does not promise multiple named accounts for every connector, nor Gmail, LinkedIn, Reddit or Instagram OAuth connections.

For a new named account, the connector's authentication definition, live verifier, supported driver methods and per-call credential use must all be present. Bridge session isolation supplies the provider-process boundary; it does not supply those vendor-specific pieces.

## Remaining delivery and verification

- Run the release's affected-package and repository checks against its final commit, verify packed installation and the pinned bridge binary, then publish the coordinated npm packages. Source merge and the Go release alone do not complete these steps.
- Supabase Vault has an actual-extension proof using standard non-superuser administrator permissions in `supabase/postgres:17.6.1.136`. That is not proof of every hosted project's grants/version; validate the target deployment's gateway and scoped login. The [verification procedure](../../connectors/supabase/README.md#verification) uses a disposable database, not production.
- Managed Cloud GCP KMS storage remains separate work in [#470](https://github.com/Sanoma-AI/sanoma/issues/470). This release does not establish a deployed Cloud identity route, tenant IAM isolation or the required live deployment evidence.
- OAuth consent, renewal, Reconnect, Disconnect and Revoke are built ([connecting by OAuth consent](README.md#connecting-by-oauth-consent), [renewal](README.md#renewal-reconnect-disconnect-and-revoke)). A live renewal against Supabase is not yet recorded.
- Moving between stores is the `migrate-store` workflow ([Moving between stores](README.md#moving-between-stores)). Changing a binding or namespace alone still transfers nothing; automated encryption-key rotation is absent.
- AWS Secrets Manager [#462](https://github.com/Sanoma-AI/sanoma/issues/462) and HashiCorp Vault [#464](https://github.com/Sanoma-AI/sanoma/issues/464) are deferred. Cloudflare host bootstrap delivery is supported as read-only startup values; the account-wide Secrets Store has no adapter, for the reasons in its row above.

## Trust limits

What still sees a credential in the clear, and what the runtime does not promise. [`secret-leakage.test.ts`](test/secret-leakage.test.ts), [`secret-isolation.test.ts`](test/secret-isolation.test.ts) and [`oauth-lifecycle.test.ts`](test/oauth-lifecycle.test.ts) check the rest with sentinels in every column of the database (`findSentinels` in `@sanoma-ai/testing`).

- **The worker and any process making a direct call.** A bundle is read and opened per call, inside the call, and lives in that process's memory while the driver runs. Code authorized for a credential (a connector's driver, a verifier, an agent's operation) can use it as it likes: encryption is not a sandbox for that code. Errors are cleared of what the driver read; a result is recorded as the driver returns it, and so is what a driver logs.
- **The provider bridge.** The bridge sidecar and its provider process are given a resource's resolved write-only fields and the provider's credentials over the socket, in the clear, and their diagnostics may repeat them. The runtime takes out of an error the values the driver read, as written: a value shorter than eight characters, or one the provider encoded, hashed or cut, is not recognized.
- **The host's environment at start.** A Cloudflare host's Worker and container are given their secrets, `SANOMA_SECRETS_KEY` and `SANOMA_SIGNING_KEY` among them, as plain environment values, uploaded through the host vendor's API from the machine that applies (which resolves `_FILE` inputs). Anything running in the container can read them, and the secrets key opens every value the built-in store keeps.
- **The built-in store's key.** A sealed value is bound to its key, namespace and name, not to its database or company: a row copied to another database opens there under the same key and namespace. Each company's key (and each preview's) must be its own.
- **Revocation windows.** Disconnect deletes the stored grant, and the next call in any process is refused (a named connection's bundle is read per call; only the change driver keeps a GitHub installation token it minted, while that token holds), but a call already at the provider completes and an access token stays valid at the vendor until it expires unless Revoke ends it there. A refresh token sent without an answer may be spent, so the account waits for Reconnect.
- **Not checked.** Process output (a connector's own logging), agent prompts beyond what operations return, and the database's administrators, who hold the ciphertext and may hold the key.
