# packages/workflows/src

The source of `@sanoma-ai/workflows`: how connectors, workflows and policies are declared, how a worker runs them durably on DBOS, and the tools that read them (lint, outline, describe). Its entry points, from `exports` in `package.json`: `.` (`index.ts`), `./describe`, `./fake`, `./plugin`, `./resources` (`secret.ts`), `./scenario`, `./scenarios` and `./shared`.

## Contents

| Path                                 | What it is                                                                                                                                                                                                                                                                        |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`apply.ts`](apply.ts)               | The built-in `apply` workflow (linted as any workflow): plans each declared resource (`ApplyPlan`), one approval where the policy holds a change, runs each step and keeps the lockfile, the `ApplyReport`                                                                        |
| [`apply-steps.ts`](apply-steps.ts)   | Internal: apply's steps that call no vendor (read the data files and the rebinds, ask the policy ahead, write and commit the lockfile), each reading its run from `currentRun`                                                                                                    |
| [`approvals.ts`](approvals.ts)       | Approval events, decision messages and the durable wait for a decision                                                                                                                                                                                                            |
| [`ast.ts`](ast.ts)                   | Shared oxc parsing, `readSource` (a file read and parsed once), tree walking, line numbers and syntax problems for the lints, outline and reader                                                                                                                                  |
| [`call.ts`](call.ts)                 | Builds a workflow's `ctx`: each call placed in the outline, then policy, approval, driver call and ledger write with the step's name; `isInfrastructureError`                                                                                                                     |
| [`client.ts`](client.ts)             | `SanomaClient`: starts runs and drift checks, lists them, decides approvals, and sets and reads credentials                                                                                                                                                                       |
| [`config.ts`](config.ts)             | `SanomaConfig`, `defineConfig`, `rootOf` (the root alone, for a read that needs no more) and `resolveConfig`: the connectors' drivers and fakes, the app name and `scenarios/` from the root, the built-ins `drift` and `apply`, each driver's `env` guard                        |
| [`cucumber.ts`](cucumber.ts)         | Internal: Cucumber as Sanoma runs it: `buildLibrary` (a support code library from data, one step definition per expression handing its step to the run's World) and `runFeatures` (a serial, in-process run of literal paths, read back with Cucumber's `Query`)                  |
| [`credentials.ts`](credentials.ts)   | Internal: the `sanoma_credentials` table, its reads and writes (AES-256-GCM under `SANOMA_SECRETS_KEY`, plaintext rows read), `storedSecrets` (a live driver's `call.secrets`) and the worker's load-and-listen of stored values                                                  |
| [`datafile.ts`](datafile.ts)         | `readDataFile`: the data-file subset over an oxc ESTree program, for the reader and both lints                                                                                                                                                                                    |
| [`db.ts`](db.ts)                     | Internal: what the runtime's tables share: `prepareDatabase` (the database, DBOS's tables, both of ours and its idle-transaction timeout, once per URL), `lazyPool` over it, `pgCode`, a racing create; `DBOS_DATABASE_OPTIONS` and `dbosClient`, what every DBOS handle is given |
| [`define.ts`](define.ts)             | `defineWorkflow` and the types for principals, approvers, approval requests and built-ins                                                                                                                                                                                         |
| [`describe.ts`](describe.ts)         | `describeConfig` and `outlineWorkflow`, re-exporting the reader: the config as plain JSON for a UI, each workflow with its file's problems, the data files' beside                                                                                                                |
| [`drift.ts`](drift.ts)               | The built-in `drift` workflow (linted as any workflow): declared resources against their vendors, the `DriftReport`; what apply shares of it (`observeBy`, `observed`, `compare`)                                                                                                 |
| [`env.ts`](env.ts)                   | A driver's `env` against an environment: `CredentialStatus`, `credentialsOf` by vendor, `unconfigured`, the one message for a vendor that cannot run, and `unconfiguredSummary`, the worker's line at start                                                                       |
| [`expectations.ts`](expectations.ts) | Internal: `detailOf`, what each generic `Then` step checks against a run's ledger records (pure)                                                                                                                                                                                  |
| [`errors.ts`](errors.ts)             | Error codes, `SanomaError` and its subclasses, input parsing, `errorInfo` and `isRunControlError` (no import of the call path, which `drift.ts` must not reach)                                                                                                                   |
| [`fake.ts`](fake.ts)                 | `defineFake`: fake vendors for tests                                                                                                                                                                                                                                              |
| [`fill.ts`](fill.ts)                 | Internal: seeded made-up values for zod schemas (scenario inputs); `shapeOf`, `isBug`                                                                                                                                                                                             |
| [`index.ts`](index.ts)               | The main entry; re-exports the public API                                                                                                                                                                                                                                         |
| [`ledger.ts`](ledger.ts)             | The audit record of a run, with Postgres (the default), JSONL and in-memory stores, and `ownedLedger` (the worker's and the client's own store)                                                                                                                                   |
| [`lint.ts`](lint.ts)                 | Internal: `lintWorkflow` (import rules oxlint cannot express, and `run` against its outline; over source or a `readSource` file) and `lintResources` (the data-file subset)                                                                                                       |
| [`lockfile.ts`](lockfile.ts)         | The lockfile, `resources/sanoma.lock.json`: which vendor object each declaration means; `readLockfile`, `serializeLockfile`, `writeLockfile` (whole or not at all), `diffLockfiles`                                                                                               |
| [`log.ts`](log.ts)                   | Operator messages (`info`, `warn`) and DBOS's (`dbosLogger`, installed without OTLP, quiet on a sandbox run's warnings and failure: `quietIfSandbox`) at the last `startWorker`'s `logLevel`; value formatting for messages                                                       |
| [`op.ts`](op.ts)                     | `defineConnector`, operations, effects and drivers; `withSetup`, a connector's driver and fake on its `[VENDOR]` record (a registered symbol, read across copies, of shape `CONNECTOR_FORMAT`), and the internal `setupOf` and `checkConnector`                                   |
| [`outline.ts`](outline.ts)           | `outlineWorkflow`: the calls (with step names), loops (with labels from the code), branches, tries and `ctx.all` groups of a workflow's `run`, by path; `callAt` places a call                                                                                                    |
| [`plugin.ts`](plugin.ts)             | The oxlint JS plugin `sanoma`, its rule `data-file` (the `./plugin` entry); `oxlint.json` loads it from `dist/`                                                                                                                                                                   |
| [`paths.ts`](paths.ts)               | Where a relative import may reach: `nearestDir` and `inside`, for both lints and the reader; `upFrom`, the one walk up the directories (`version.ts` finds DBOS's `package.json` with it)                                                                                         |
| [`policy.ts`](policy.ts)             | Policy types, decisions (`allow`, `deny`, `approve`), `definePolicy` and `approvedFor`                                                                                                                                                                                            |
| [`resource.ts`](resource.ts)         | `defineResource`: a resource type's schema, fields, references, `read` and `import`; `compareDeclared`, `diffDeclared`                                                                                                                                                            |
| [`resources.ts`](resources.ts)       | `readDataFiles` and `readResources`: the resources the data files declare, joined to their bindings, the orphaned bindings, and the problems                                                                                                                                      |
| [`run.ts`](run.ts)                   | The per-run and per-worker state the DBOS workflow receives, and `currentRun`, the run whose body is running                                                                                                                                                                      |
| [`sandbox.ts`](sandbox.ts)           | `seedSandbox`: a sandbox run's own copies of the fakes, seeded; the worker imports it only for such a run                                                                                                                                                                         |
| [`scenario.ts`](scenario.ts)         | Gherkin scenarios on Cucumber: the generic steps, the connectors' and the phrases as rules, `loadScenarios` (compile), `check` (a run's `Then` steps), `testFeature` (an operation's own test), `featureScenarios` (a dry run) and `drive`                                        |
| [`steps.ts`](steps.ts)               | `defineSteps` and its types (`Seed`, `Expect`, `RunView`): a connector's or a company's steps as data, free of Cucumber                                                                                                                                                           |
| [`secret.ts`](secret.ts)             | The `./resources` entry: `secret()` and its marker, `resolveSecrets` (a driver's), `memorySecrets` (fakes', sandbox runs' and tests')                                                                                                                                             |
| [`source.ts`](source.ts)             | The `Source` type: the company's repository, which the runtime's writers commit through; the built-in `sanoma.source.resolve` (`git ls-remote`), registered by `config.ts` for a host type                                                                                        |
| [`host.ts`](host.ts)                 | The `Host` contract: `HostSpec` (a resource type's `host`), its capabilities and outputs, and `checkHost`, which `defineResource` runs                                                                                                                                            |
| [`writer.ts`](writer.ts)             | The data-file writer: `setFields` (one declaration's fields, the rest of the file byte for byte), `renderDataFile`, `formatOptions`; formatted with oxfmt                                                                                                                         |
| [`shared.ts`](shared.ts)             | Browser-safe helpers for run status and approvals, `DRIFT_WORKFLOW`, and resource types; no DBOS, Node or zod                                                                                                                                                                     |
| [`scenarios.ts`](scenarios.ts)       | `runScenario` (one, as a sandbox run) and `runScenarios` (every scenario of a config on a worker it starts), with no test framework                                                                                                                                               |
| [`version.ts`](version.ts)           | The package version, the step layout and `computeVersion`, the application version hash                                                                                                                                                                                           |
| [`worker.ts`](worker.ts)             | `startWorker`: reads each workflow's outline, loads stored credentials, launches DBOS (with `dbosLogger`), registers each workflow by name, returns a stoppable `Worker` naming the vendors not configured                                                                        |
