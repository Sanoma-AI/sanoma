# packages/bridge/test

Tests for `@sanoma-ai/bridge`, and the helpers that replay and record the bridge for them. All but `live.test.ts` run offline.

## Contents

| Path                                     | What it is                                                                                                                                                                                                                     |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [`fake.test.ts`](fake.test.ts)           | `readPins`; `fakeBridge` over the checked-in GitHub and Stripe fixtures and `hashicorp/null`'s recorded change, and the errors it gives; a live run without its `needs`; no credentials in any fixture                         |
| [`bin.test.ts`](bin.test.ts)             | `bridgeBin`'s order over a fake package layout; `downloadRelease` from a stubbed `fetch`: extraction with the licenses, a sha256 mismatch, no pin                                                                              |
| [`errors.test.ts`](errors.test.ts)       | Connect errors and diagnostics as `BridgeError`; `startBridge` without a binary or with one that exits                                                                                                                         |
| [`configure.test.ts`](configure.test.ts) | `ensureConfigured`: once per config, close and configure on a change (once for concurrent calls), after `unavailable`, and a retry when not configured                                                                         |
| [`lazy.test.ts`](lazy.test.ts)           | `lazyBridge` over a stub `start`: one start for many calls, a retry after a failed start (as `DriverError`), a restart after any `unavailable`, configured afresh, `stop`; `defaultBridge` is one                              |
| [`replies.test.ts`](replies.test.ts)     | `loadReplies` (a read without its import too) and `stateBridge`: the bridge's refusals, recorded failures, `gone`, plans and applies                                                                                           |
| [`record.test.ts`](record.test.ts)       | The recorder's scrubbing and change layout, against an in-memory provider, and `fakeBridge` replaying what it wrote                                                                                                            |
| [`change.test.ts`](change.test.ts)       | A writable type's change operations over `hashicorp/null`'s recorded plans and applies: create, no-op update, replace, delete, `plan_changed`, and write-only scrubbing of a secret the provider does not mark; `resourcePath` |
| [`tfschema.test.ts`](tfschema.test.ts)   | `ctyToZod` per cty type, `generateResources`, `fromTfState` and `toTfState`, and the CLI                                                                                                                                       |
| [`live.test.ts`](live.test.ts)           | `SANOMA_LIVE=1` only: builds the bridge, runs `hashicorp/null` (schema, configure, read, errors, a change), records and replays through `fakeBridge`                                                                           |
| [`fake-bridge.ts`](fake-bridge.ts)       | Helper, not published: `fakeBridge`, `BridgeService` over fixture files on an in-memory transport; live (`SANOMA_LIVE=1`, with its `needs`) and recording (`SANOMA_RECORD=1`) modes                                            |
| [`change-replay.ts`](change-replay.ts)   | Helper, not published: `changeReplay`, a bridge replaying recorded `plan.json` and `apply.json` replies; it records the calls it gets, in order                                                                                |
| [`record.ts`](record.ts)                 | Helper, not published: `recorder(dir)`, a Connect interceptor writing scrubbed fixtures; the reply paths, how a change is matched, and the hint `fakeBridge` gives when one is missing                                         |
