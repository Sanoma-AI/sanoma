# Working on @sanoma-ai/desktop

This package is the desktop shell (private, never published): an Electron app that opens a company folder, runs that repo's own `node_modules/sanoma` launcher with the Node it ships, and shows the app in a window. The [README](README.md) says what it does.

- `src/main.ts` is wiring only (the window, menus, Dock menu, tray, IPC, single instance, quit) and the one module that imports `electron`, with the two preloads, which Vite builds as CommonJS, as a sandboxed preload must be: `src/preload.ts`, the bridge of the shell's own pages (`start/index.html`, the start screen, and `start/company.html`, a company's progress), and `src/app-preload.ts`, the app view's. The shell has ONE window (#423), a `BaseWindow` made at launch and only hidden before Quit: the start screen's view, and per company two `WebContentsView`s, the shell's page and the app's (its own `persist:` partition), swapped in place; the shown company's (or the start screen) fill the window, every other view hidden and kept loaded. No shell chrome in the window: companies switch from the app's account menu, ⌘1…⌘9, the Window menu, the Dock menu and the tray (not macOS). Everything else is a plain Node module tested on its own: `launcher.ts` (process groups, and process trees on Windows; ready detection, the launcher's environment), `session.ts` (shims, install, launch), `create.ts` (New company's `pnpm dlx sanoma init` session, its `stage` events as steps, Clone), `git.ts` (command line tools, identity, git's environment), `update-company.ts` (Get Updates, the lockfile rule), `pages.ts` (what the pages show of a state: no Node or Electron, as the pages import it too), `events.ts`, `companies.ts` (Recent, its Local or Live read from the lockfile and `infra.ts` as text, the display name from `sanoma.config.ts`, ports, what reopens at launch), `window-state.ts` (where the window opens, which company shows once one leaves), `links.ts` (the link rule, and `isAppPage`), `shims.ts`, `logs.ts`, `places.ts`, `runtime.ts`, `quit.ts` (Quit's order: the companies stop, then the app quits or Squirrel installs an update), `self-update.ts` (which builds update themselves: `update-electron-app`, macOS and Windows), `update-check.ts` (the others' daily check). Keep logic out of `main.ts`.
- The shell never adds a runtime concept: no flag, header or User-Agent tells the app it is inside the shell. The one exception is `window.sanomaDesktop` (`app-preload.ts`; the app's `src/lib/desktop.ts` types it): the window's companies by an opaque id, never a path, switch, add and a subscription, for the account menu, and nothing else, as the page runs the company's own code. `main.ts` answers its `desktop:` messages only from a company's app view, in its top frame, at its app's origin (`isAppPage`); keep it that small. What the shell needs from the launcher goes through its command line and `SANOMA_EVENTS` lines (#286 L1), with the 0.6.0 fallbacks kept while older launchers are in use.
- Electron Forge from its Vite + TypeScript template (`forge.config.mts`, `vite.main.config.mts` (main and preload), `vite.renderer.config.mts`): Vite bundles `src/main.ts` and `src/preload.ts` into `.vite/build` and the pages in `start/` into `.vite/renderer/start` (`START_VITE_*`, and `SIGNED_BUILD` from `vite.main.config.mts`: `src/declarations.d.ts`). No runtime dependencies in the package: what the shell imports is bundled; Node and pnpm are staged into `stage/` by `scripts/stage.ts` and copied into the app's resources. The start screen and a company's page are plain HTML and JavaScript in `start/`, with relative URLs only (Vite builds it with `base: "./"`), on the app's tokens and fonts (`start/style.css`, by hand from the app's `ui.css`, so change them together). The app keeps Sanoma's mark (`packages/sanoma/app/src/icon.svg`, `icon-small.svg`): the start screen imports the small one, and `icons/` holds the app icons drawn from both, checked in ([how](README.md#the-icon)).
- What the shell has to say goes in its window (a company's page, or the start screen's notice line), never in a native `dialog.showMessageBox`, which holds up the main process (and the smoke test) until someone clicks it. Native dialogs are for the folder pickers and the confirmations that need an answer (Apple's command line tools, Git for Windows, Help's update check).
- A company's app view gets only `app-preload.ts` and stays sandboxed; the windows it opens get no preload; links follow `linkTarget` in `src/links.ts`.

Run `pnpm vitest run packages/desktop`: the process manager against a fake launcher (`test/fixtures/launcher.mjs`) and a fake pnpm, the pure modules, and the git modules against temporary repositories (`test/git.test.ts`, with a git config of their own). Electron itself is started only by the smoke test, `pnpm --filter @sanoma-ai/desktop run test:e2e` (`test/e2e`, Playwright, a fixture company in `test/fixtures/company`), which CI runs in `desktop.yml` for changes here, with the unit tests on Windows (code that differs there takes a `platform` argument, so its Windows branch is tested on macOS too). On Windows the same workflow also builds the packaged app and runs the smoke test on it (`SANOMA_DESKTOP_EXE`, with a `SANOMA_TEST_BUILD` build, the only one Playwright can attach to), `test/e2e/new-company.spec.ts` (a real `pnpm dlx sanoma`, from a local registry, `test/registry/verdaccio.yaml`, holding this commit's packages) and the installer (`scripts/check-windows-install.ps1`). `pnpm --filter @sanoma-ai/desktop package` builds the app for this computer into `out/`, `make` builds the macOS installers for arm64 and x64 into `out/make` (a dmg and a zip), and `make:windows` the Squirrel installer for x64; `.github/workflows/desktop-release.yml` runs them and, when both pass, uploads one draft GitHub Release. Without the `APPLE_*` variables the build is signed ad hoc, which `start` and the smoke test rely on; change `node.entitlements.plist` only with a signed build to try it on, as a missing entitlement shows only there ([signing](README.md#signing-and-notarization)). To try the shell, `pnpm --filter @sanoma-ai/desktop start <company folder>`.
