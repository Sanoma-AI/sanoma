# Working on @sanoma-ai/desktop

This package is the desktop shell (private, never published): an Electron app that opens a company folder, runs that repo's own `node_modules/sanoma` launcher with the Node it ships, and shows the app in a window. The [README](README.md) says what it does.

- `src/main.ts` is wiring only (windows, menu, Dock menu, IPC, single instance, quit) and the one module that imports `electron`, with `src/preload.cts` (the bridge of the shell's own pages, `start/index.html` for the start window and `start/company.html` for a company window's progress; CommonJS, as a sandboxed preload must be). A company window is one `BaseWindow` with two `WebContentsView`s, the shell's page and the app's (its own `persist:` partition), swapped in place; closing it hides it while the company runs. Everything else is a plain Node module tested on its own: `launcher.ts` (process groups, ready detection, the launcher's environment), `session.ts` (shims, install, launch), `create.ts` (New company's `pnpm dlx sanoma` session, Clone), `git.ts` (command line tools, identity, git's environment), `update-company.ts` (Get Updates, the lockfile rule), `events.ts`, `companies.ts` (Recent, ports, what reopens at launch), `window-state.ts` (where a window opens), `links.ts`, `shims.ts`, `logs.ts`, `places.ts`, `runtime.ts`, `update-check.ts`. Keep logic out of `main.ts`.
- The shell never adds a runtime concept: no flag, header or User-Agent tells the app it is inside the shell. What the shell needs from the launcher goes through its command line and `SANOMA_EVENTS` lines (#286 L1), with the 0.6.0 fallbacks kept while older launchers are in use.
- No runtime dependencies (`electron` and `electron-builder` are devDependencies; Node and pnpm are staged into `stage/` by `scripts/stage.ts` and copied into the app's resources). The start window is plain HTML and JavaScript in `start/`.
- What the shell has to say goes in its windows (a company's page, or the start window's notice line), never in a native `dialog.showMessageBox`, which holds up the main process (and the smoke test) until someone clicks it. Native dialogs are for the folder pickers and the confirmations that need an answer (Apple's command line tools, an iCloud folder, Help's update check).
- A company's app view gets no preload and stays sandboxed; links follow `linkTarget` in `src/links.ts`.

Run `pnpm vitest run packages/desktop`: the process manager against a fake launcher (`test/fixtures/launcher.mjs`) and a fake pnpm, the pure modules, and the git modules against temporary repositories (`test/git.test.ts`, with a git config of their own). Electron itself is started only by the smoke test, `pnpm --filter @sanoma-ai/desktop run test:e2e` (`test/e2e`, Playwright, a fixture company in `test/fixtures/company`), which CI runs in `desktop.yml` for changes here. `pnpm --filter @sanoma-ai/desktop dist` packs the dmg and zip for both architectures (`electron-builder.yml`); `.github/workflows/desktop-release.yml` runs it and uploads a draft GitHub Release. To try the shell, `pnpm --filter @sanoma-ai/desktop start <company folder>`.
