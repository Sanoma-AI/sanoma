# packages/postgres-bin

One package per platform, `@sanoma-ai/postgres-<platform>` (`darwin-arm64`, `darwin-x64`, `linux-arm64`, `linux-x64`, `win32-x64`), each carrying the PostgreSQL 18 server (`bin/` holds `initdb`, `pg_ctl` and `postgres`; `lib/` and `share/` what they load) that the `sanoma` launcher is to start a company's own database from.

- The payload, `postgres.tar.gz` and `postgres.json` (`{ "postgres": <version>, "sha256": <the archive's> }`), is absent in the checkout (gitignored). `pnpm postgres:download` fills this machine's package, and each package's `prepack` its own, with [`../sanoma/scripts/download-postgres.ts`](../sanoma/scripts/download-postgres.ts) `--platform <platform>`: zonky's jar of the release `RELEASE` pins, from Maven Central, checked against its sha256. `postpack` removes the payload. `pnpm postgres:download --check` extracts this machine's archive into a temporary directory and runs `bin/postgres --version`; CI fills all five (cached on the script's hash), so the darwin and Windows steps run on Linux as in a release, and checks linux-x64.
- The binaries ship inside a gzip tarball, not as files: npm tarballs drop symlinks and execute bits, and the libraries need both. The darwin jars are universal and store each library alias as a full copy; the script keeps the package's architecture of every Mach-O file (in Node, so a darwin package packs on Linux) and makes byte-identical libraries symlinks. On Windows it drops the `wx*.dll` files and `share/locale`.
- No `bin`, install scripts or dependencies. `os` and `cpu` sit in `publishConfig`, which pnpm copies into the published manifest (in the manifest itself pnpm would warn about the other platforms on every install); `win32-x64` lists `arm64` too, which runs x64 binaries. `LICENSE` names the PostgreSQL Licence and the bundled libraries' licences for that platform.
- Each package has its own version; the server's is `RELEASE.version`. To ship another PostgreSQL release, update `RELEASE` with the new jars' sha256s (computed by hand) and release a new version of the five packages: a version already on npm never carries new binaries. A new platform package needs a first publish by hand and its npm trusted publisher before `release.yml` can publish it.
