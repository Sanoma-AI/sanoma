# packages/postgres-bin

One package per platform, `@sanoma-ai/postgres-<platform>` (`darwin-arm64`, `darwin-x64`, `linux-arm64`, `linux-x64`, `win32-x64`), each carrying the PostgreSQL 18 server (`bin/` holds `initdb`, `pg_ctl` and `postgres`; `lib/` and `share/` what they load) that the `sanoma` launcher is to start a company's own database from.

- The payload, `postgres.tar.gz` and `postgres.json`, is absent in the checkout (gitignored). Each package's `prepack` fills it with [`../sanoma/scripts/download-postgres.ts`](../sanoma/scripts/download-postgres.ts) `--platform <platform>` (its header says what it does and how to run it), and `postpack` removes it. `pnpm postgres:download` fills this machine's package. CI runs the five prepacks (cached on the script and the manifests), so the darwin and Windows steps run on Linux as in a release, then `--check` on linux-x64.
- The binaries ship inside a gzip tarball, not as files: npm tarballs drop symlinks and execute bits, and the libraries need both.
- No `bin`, install scripts or dependencies. `os` and `cpu` sit in `publishConfig`, which pnpm copies into the published manifest (in the manifest itself pnpm would warn about the other platforms on every install); `win32-x64` lists `arm64` too, which runs x64 binaries. `LICENSE` names the PostgreSQL Licence and the bundled libraries' licences for that platform.
- Each package has its own version; the server's is `RELEASE.version`. To ship another PostgreSQL release, update `RELEASE` with the new jars' sha256s (computed by hand) and release a new version of the five packages: a version already on npm never carries new binaries. A new platform package needs a first publish by hand and its npm trusted publisher before `release.yml` can publish it.
