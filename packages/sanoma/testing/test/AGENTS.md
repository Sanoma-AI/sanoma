# packages/sanoma/testing/test

Tests for `sanoma/testing`. `harness.test.ts`, `scenarios.test.ts`, `host.test.ts`, `wakeup.test.ts`, `database.test.ts`, `sentinel.test.ts` and `stack.test.ts` need Postgres (`pnpm db:up`).

## Contents

| Path                                     | What it is                                                                                                                                                                                                                                                                                                                                            |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`database.test.ts`](database.test.ts)   | `checkDatabase` against `fakeDatabase` (the fourth check after a suspend that drops the worker's and the client's connections), the rest failed at once when none starts; the fake in a config, its `storeUrl`, apply and removal                                                                                                                     |
| [`fakes.test.ts`](fakes.test.ts)         | The connector fakes: idempotent replays, injected faults, `update` and a shared call log                                                                                                                                                                                                                                                              |
| [`harness.test.ts`](harness.test.ts)     | `useTestApp`: one config, so the client reads both runs across a restart                                                                                                                                                                                                                                                                              |
| [`host.test.ts`](host.test.ts)           | `checkHost` against `fakeHost` over `inProcessHost`, long-lived, `stops-on-exit` (the checks of a host that stops, its runtime ending once idle under a stubbed wake route), and that with a `hostname` that never resolves (the kit reaches its `wakeUrl`); the proxy kept across a stop and the runtime's end, started again on the next request    |
| [`wakeup.test.ts`](wakeup.test.ts)       | `checkWakeup` against `fakeWakeup` over a `stops-on-exit` `fakeHost`, its schedule's tick among the checks; `fire()`, a wake sent again until the host answers, and the fake declared in a data file for the host it names                                                                                                                            |
| [`stack.test.ts`](stack.test.ts)         | Scale to zero on fakes: a `stops-on-exit` `fakeHost` over `inProcessHost`, `fakeWakeup` applied for it, a sleeping run and a schedule; the worker stops idle, the process stops, wakes start it and a fresh worker                                                                                                                                    |
| [`sandbox.test.ts`](sandbox.test.ts)     | `checkSandbox` against `fakeSandbox`, the checks a backend does not declare left out and the rest failed at once when no box opens; the fake in a config                                                                                                                                                                                              |

| [`sentinel.test.ts`](sentinel.test.ts)   | `findSentinels` on a database of its own: the schema, table and column of each sentinel a text, `jsonb` or array column holds, bytes left out; a sentinel it could not find as written refused                                                                                                                                                        |
| [`fixtures/`](fixtures/)                 | A root with a config of the workflows package's announce workflow on the packages' connectors, a copy of its announce scenarios in `scenarios/`, a root with a broken feature file (`broken/scenarios/`), a root with a world alone (`world/scenarios/world.feature`), and the vitest config that runs `broken.scenarios.ts` and `world.scenarios.ts` |
