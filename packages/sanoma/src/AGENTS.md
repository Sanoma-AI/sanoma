# packages/sanoma/src

The source of `sanoma`: the bin (`cli.ts`, `dist/cli.js` once built) and the modules it is made of, and the package's entries, `index.ts` and `resources.ts` (`sanoma/resources`); `sanoma/site` and `sanoma/ui` are `../site.js` and `../ui.js`, outside `src/` (see the [package's guide](../AGENTS.md)).

## Contents

| Path                                   | What it is                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`cli.ts`](cli.ts)                     | The bin: `sanoma` (the sites on the dev server), `serve` (hidden: builds them; `--dev` for dev mode's child), `api` (hidden: writes `.sanoma/api.ts`), `worker`, `app`, `check`, `env`, `ledger export`, `--help`; signals, exit codes (a problem in the policies is a usage error but for `check`); each command imported when run                                                                                                                                                                                                      |
| [`check.ts`](check.ts)                 | `check`: the policies' problems (`policyProblems`, as `resolveConfig` reads them), the generated files (`writeGenerated`), then a site's files; tsc, oxlint on the repo's `.oxlintrc.json` (written when missing), `describeConfig`'s problems and the sites (the app built with them, a denied import at its line, `tsc -p sites/tsconfig.json`) at once, folders refused as sites, the content's problems (`readContent`), then `runScenarios` once Postgres is `ready`; one line each, and the sites' `warnings`, which never fail it |
| [`config.ts`](config.ts)               | `loadConfig`: `.env`, then `sanoma.config.ts`'s default export, with its root, and the collections `resources/data.ts` exports; `UsageError`                                                                                                                                                                                                                                                                                                                                                                                             |
| [`dev.ts`](dev.ts)                     | Dev mode: `linkedPackages` (the linked packages and the core packages reached through them, found by `module.findPackageJSON`), `devRepo`, `partialLink` (the core packages a partial link leaves installed), `supervise` (restart on a change under `dist/`, but for the directories it ignores), `whenUnlinked` (the repo no longer links the checkout: dev mode ends), `startWatchers` (each package's `watch`), `end` (a process group)                                                                                              |
| [`env.ts`](env.ts)                     | `renderEnvExample` and `writeEnvExample`: `.env.example` from the variables the drivers declare                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| [`init.ts`](init.ts)                   | `startCompany`: `sanoma` in an empty directory: the template, the package's name, its creator as the first person in `resources/people.ts` (`whoIsStarting`, `declareFounder`), `.env`, the install (`packageManagerOf`), the first commit                                                                                                                                                                                                                                                                                               |
| [`key.ts`](key.ts)                     | `addToEnv` (variables a `.env` lacks); `writeSecretsKey`, the one writer of `SANOMA_SECRETS_KEY` (`startCompany`'s too); `ensureSecretsKey`: one made when missing, before `serve` starts the worker                                                                                                                                                                                                                                                                                                                                     |
| [`index.ts`](index.ts)                 | What a company repo imports: the names the lint lets a workflow import (`z` among them), `defineConfig`, the ledger stores, types; Node's types, by a preserved reference                                                                                                                                                                                                                                                                                                                                                                |
| [`oxlint-plugin.ts`](oxlint-plugin.ts) | The oxlint plugin `sanoma`: `@sanoma-ai/workflows/plugin`'s `data-file` and `date`, and `site-file`, for the generated `oxlint.json` to load from `dist/`                                                                                                                                                                                                                                                                                                                                                                                |
| [`ledger.ts`](ledger.ts)               | `exportLedger`: a run's records through a `SanomaClient`, as JSON lines                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| [`postgres.ts`](postgres.ts)           | `ensurePostgres`: probe the URL, else (on a loopback host, `isLoopback`) start or create `sanoma-<appName>-postgres` in Docker and wait for it; `masked`                                                                                                                                                                                                                                                                                                                                                                                 |
| [`resources.ts`](resources.ts)         | The `sanoma/resources` entry, for data files: `secret` and `sanoma` (people, agents, groups)                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| [`data.ts`](data.ts)                   | The `sanoma/data` entry, for `resources/data.ts`: `collection` and its types, all `@sanoma-ai/workflows/data` exports                                                                                                                                                                                                                                                                                                                                                                                                                    |
| [`site-lint.ts`](site-lint.ts)         | `siteFile`, the rule `sanoma/site-file`: under `sites/`, no `*.server.*` file, `createServerFn`, `createServerOnlyFn` or `createMiddleware`, `server` in `createFileRoute`'s options, or relative import out of `sites/`                                                                                                                                                                                                                                                                                                                 |
| [`sites.ts`](sites.ts)                 | `siteBuild` (`@sanoma-ai/app/build`, loaded only when `sites/` exists), `runtimeFrom` (this package's `package.json`, where the build's runtime resolves)                                                                                                                                                                                                                                                                                                                                                                                |
| [`serve.ts`](serve.ts)                 | `runWorker`, `runApp`, `serve`: the worker (promoted) and the app, stoppable, each given the config's checkout as `source`; writes `.sanoma/api.ts` first, and on the dev server's config changes through a child `sanoma api`; the app served from its build with the repo's sites when there are any (built before the worker starts), or with `dev` and a loopback host from the dev server; `appOptions`: the app's host and GitHub sign-in from the environment, or the stored App's client                                         |
| [`source.ts`](source.ts)               | `localGitSource`: the repo's git checkout as the runtime's `Source`, committing on the current branch                                                                                                                                                                                                                                                                                                                                                                                                                                    |
