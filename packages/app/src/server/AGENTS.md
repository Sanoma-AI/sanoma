# packages/app/src/server

Server-only code behind the app's server functions.

## Contents

| Path                           | What it is                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [`available.ts`](available.ts) | The connector packages on npm (the page leaves out the installed ones): the keyword search, each one's latest version and its `sanoma` field, its logos read from jsDelivr and checked as installed ones are (`data:` URLs); an empty list saying why when npm cannot be searched                                                                                                                                                                                                                      |
| [`core.ts`](core.ts)           | Who is asking and actor checks, the server functions' validators, run detail (with a sandbox run's checks), the runs, the scenarios, start (of a workflow or a scenario) and decide calls, a site's `api` call (`callApi`: an operation, or a workflow started or its runs read, by name), the credentials' statuses, set and clear, Adopt (a drifted field's value at the vendor into its data file, committed through the app's `source`), and what a server function fails with (`serverFnFailure`) |
| [`go-live.ts`](go-live.ts)     | Going live after connect: the choices (GitHub accounts from the token and the App's installations, Supabase organizations and regions, the host type), `infra.ts` rendered and committed, apply on the repository and the database, the push, apply on the host, and the progress told from the files, the lockfile and the runs                                                                                                                                                                       |
| [`models.ts`](models.ts)       | `modelRegistry(app)`: one AI SDK registry over the connectors' model halves (`<vendor>/<model-id>`, `<vendor>/default`), made once per resolved config and client, its keys read through the client's secrets at each call                                                                                                                                                                                                                                                                             |
| [`setup.ts`](setup.ts)         | Connecting GitHub and Supabase: the GitHub App's manifest page and callback (state and who asked in a signed cookie, keys stored encrypted as set by them), the connect page's status, and its pasted tokens; connecting an existing repository or project (`connectExisting`): imported, declared in `infra.ts`, committed (on a branch when there is a remote) and bound by apply                                                                                                                    |
