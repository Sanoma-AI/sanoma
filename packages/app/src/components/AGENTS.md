## Layout conventions

- Spacing scale: `gap-(--gap-region)` between a page's regions, `gap-(--card-spacing)` inside a card (Card's own variable), `gap-(--gap-section)` inside a section (a titled one is a `Region`), `gap-2` inside an item.
- Compact (`data-density="compact"` on `#app`, chosen under Density in the user menu) sets Tailwind's `--spacing` on the page (`data-slot="page"`), which cards and every spacing utility follow, and re-sets `--gap-region` and `--gap-section`; see `src/style.css`. The panes' heights are `style.css`'s `--pane*` tokens (`h-(--pane)`). The `compact:` variant is for a few deliberate extra cuts on top of the unit: the card headers' padding and `Facts`' row gap. Items follow the unit alone. The bar and the chat column keep the full unit, as their widths are fixed.
- A link drawn as a button is a `ButtonLink`, never `Button` with `render` (even with `nativeButton={false}`, as the shadcn skill shows): Base UI's Button makes it `role="button"` and lets Space press it. A tooltip is a `Tip` (or `TipButton` on an icon button), which also gives its trigger the tip as `aria-describedby`, since Base UI's tooltip does not.
- A list page is its frame: `CrumbHeader` (or `PageHeader`) with the list's `count` and its actions, `LinkTabs` for its views (each a URL), then one `Card` (`gap-0 py-0`) holding a toolbar row (`p-3`: a find box, selects) and the table or list flush to its edges, an empty state inside it (`Nothing` with `border-0`). The item open floats over the card's right as a `FloatingCard`, placed by `common.tsx`'s `FLOAT_CARD` (the card, a `@container`), `FLOAT` (the float: `absolute` from `@3xl` of the card's own width, `top-3 right-3`, as tall as its content up to the card's, `w-(--float-width)`, which Compact leaves as is; in the flow below `@3xl`) and `FLOAT_ROOM` (the list padded clear of it), above the list (`order-first`) on a narrow page (the chat open), so it still reads; a list's card with its float is `FloatHost`.
- A workflow's page is its frame too: `CrumbHeader` with New run, `LinkTabs` Graph, Runs, Code and Scenarios (`?view=`), then one card. Its graph and its code are a [`WorkflowView`](workflow-view.tsx), the inspector floating over the graph (which runs under it) or over the code (which leaves it room); a run's page is a `WorkflowView` of the run, its Ledger and Code tabs under the graph card.
