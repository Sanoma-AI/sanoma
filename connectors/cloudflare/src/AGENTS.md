# connectors/cloudflare/src

Source of the Cloudflare connector: the three resource types, their operations over Cloudflare's API and the company's Worker, the deploy's pieces, the driver, and an in-memory fake that runs the Worker's own code.

## Contents

| Path                           | What it is                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`connector.ts`](connector.ts) | Defines `container` (a host), `alarm` (a wakeup) and `records` (a zone's DNS record set), their schemas, and `cloudflareOps` with `alarm.register`                                                                                                                                                                                                                                                                     |
| [`ops.ts`](ops.ts)             | `CloudflareApi`, and `containerOps` and `alarmOps` over it: the deploy's three steps (an upload before the bundle serving the app deployed, R's container preparing the database and building the bundle, each upload waited for until live), the Hyperdrive origin, non-starting plans, the restart alone on an unchanged update, the wake route, refusals                                                            |
| [`records.ts`](records.ts)     | `recordsOps` over `CloudflareApi`: a set found by its mark, its plan, one batch per write, adoption, conflicts and the token's DNS permission                                                                                                                                                                                                                                                                          |
| [`driver.ts`](driver.ts)       | `cloudflareDriver`: `CloudflareApi` over the `cloudflare` SDK and `fetch`, Hyperdrive configs with query caching off, failures mapped to `DriverError`, the credentials' `env`                                                                                                                                                                                                                                         |
| [`errors.ts`](errors.ts)       | `refused`: the driver's own refusal, never retried                                                                                                                                                                                                                                                                                                                                                                     |
| [`registry.ts`](registry.ts)   | `accountImage` and `copyImage`: the declared image copied into the account's registry over the OCI distribution API with `fetch`, pinned by digest                                                                                                                                                                                                                                                                     |
| [`fake.ts`](fake.ts)           | `fakeCloudflare`: an in-memory account whose Workers serve on this machine, running `worker/instance.js`'s `serve` over the upload's modules and its object over an in-process `ctx`, an upload answering after `propagation` requests, each database prepared by the revisions whose worker started over it; `stubAppBundle`, the bundle its containers answer, refusing a database without its revision's migrations |
| [`deploy.ts`](deploy.ts)       | What a deploy uploads: the package's Worker modules, the app bundle asked of the version it uploaded (`appBundle`), its modules under `app/`, its assets through an upload session                                                                                                                                                                                                                                     |
| [`steps.ts`](steps.ts)         | `cloudflareSteps`: Cloudflare's steps for Gherkin tests (`defineSteps`)                                                                                                                                                                                                                                                                                                                                                |
| [`resources.ts`](resources.ts) | The constructors data files import: `cloudflare.container`, `cloudflare.alarm`, `cloudflare.records`                                                                                                                                                                                                                                                                                                                   |
| [`index.ts`](index.ts)         | The package root: `cloudflare` with its driver, fake and steps attached (`withSetup`)                                                                                                                                                                                                                                                                                                                                  |
