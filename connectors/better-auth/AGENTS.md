## Boundaries

- Depend on `better-auth` (pinned to `1.7.x`), `pg`, and `kysely` for the `PostgresDialect` that carries `schemaName` (Better Auth's own dependency, the same copy). Nothing under a company's `sites/` imports `better-auth`: pages post JSON to `/auth/better-auth/*`.
- The migrations are the worker's (`prepareBetterAuth`, run by `startWorker` after the runtime's own tables: the connector's `prepare` for the visitor login, and the launcher's `prepare` option for the staff login), never the app's: `openBetterAuth` checks once per process that the schema's last table (`rateLimit`) is there and refuses otherwise, since on the Cloudflare host the app runs in the Worker script, which must not migrate (an advisory lock is one connection's, and Hyperdrive pools them). They run under the advisory lock `hashtext('sanoma.login.better-auth.<schema>')`, polled with `pg_try_advisory_lock` on a session of its own (as the runtime's `lockPreparation`: a blocked lock statement can deadlock with a migration Postgres cannot see), once per database and schema per process: two workers preparing at once fail without the lock, which `login.test.ts` holds it to. The table-shaping options (`TABLE_OPTIONS`: the `github` column, `rateLimit.storage: "database"`) are one constant the migrations and both logins share, so the schema the worker makes is the one the app expects.
- The staff half answers on any host (`allowedHosts: ["*"]`), which leaves Better Auth's own Origin check nothing to compare: `handle` refuses a POST whose `Origin` is not the request's host itself, and serves only the routes it lists (`ROUTES`).
- Better Auth sets no `input: false` field from a provider's profile (`parseAdditionalUserInputFromProviderProfile`), so `mapProfileToUser` cannot set `github`: the staff login admits in `user.validateUserInfo`, which Better Auth runs before any row on `create-user`, `link-account` and an OAuth `sign-in` with the raw profile (`source.oauth.profile.login`), answering `error=not_declared`; it keeps the login per request (a WeakMap on the endpoint context) and its account hooks write it (`keepLogin`), store no tokens (`dropTokens`, a `create`/`update` before-hook) and clear it when the account goes (`forgetLogin`); a new GitHub account under a login a row carries is refused (GitHub frees a renamed login), and a sign-in or link on an existing row is admitted by the row's verified email too; the visitor login's account hooks read the login from GitHub's `/user` with the account's own token on GitHub's redirect back (`noteLogin`, `/callback/:id` only), then drop the account's tokens (no GitHub grant is kept), refuse a second GitHub account (`oneGitHub`), and clear the login when the account goes (`forgetLogin`). Keep GitHub an untrusted provider for visitors (`trustedProviders` unset): a GitHub sign-in joins the account of its email only when GitHub verified that email (and, `requireLocalEmailVerified`, the account's own is verified), and a link needs GitHub's verified email too. A trusted GitHub would let an unverified GitHub email sign into someone's account, which `login.test.ts` holds it to. `allowDifferentEmails` is for the explicit link only (`/link-social`).
- `verify` lets Better Auth's errors for a Host or configuration throw; only a missing or bad cookie is null. `handle` refuses a foreign Host itself (421) before `auth.handler`, which would throw it as a 500.
- Better Auth turns its Origin check off under `NODE_ENV=test` and its rate limit off outside production: the options set both explicitly, so tests run what production runs. The rate limit's counts are rows (`storage: "database"`) and the session is cached in the cookie (`cookieCache`, five minutes): nothing of a login lives in the process, so an instance per request (the Worker's shape) is the same login.

Run `pnpm vitest run connectors/better-auth` with Postgres up (`pnpm db:up`) and the packages built (`site.test.ts` builds the fixture's app against them) and `SANOMA_TEST_DATABASE_URL` naming a database of your own.
